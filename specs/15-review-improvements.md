# Spec 15: Trustworthy advice and a useful council report

## 1. Scope

This spec turns the 9 October review into work the loop can ship. It covers the stop rule, report packages, width and crossing proof, people counts, data checks, run limits and council use. The loop must finish each row with the shipped region settings. A survey need is a result, not proof that a fix fits.

These requirements amend specs 04 to 14 where named below. New rows cite both IDs when a prior rule changes. Do not keep the old behaviour to preserve a test: add a new failing case, change the tool, and retain all prior checks that still apply. A changed policy needs a spec change first.

## 2. Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-15.1 | Use the same finite benefit ratio for ranking and the stop: gain / (cost + 1). Compare each pick with the best ratio so far, including that pick; mark the last rank at least recommend_ratio times that best value. Compute from full precision, not display-rounded gains. The report explains this exact rule. A curve records termination_reason (no_gain, candidate_pool_exhausted or project_cap), evaluated_projects (saved non-baseline steps) and truncated independently of its stop. Always disclose a truncated curve, even when its stop is earlier. Preserve stable ties. This amends FR-8.14. | MUST |
| FR-15.2 | One selected package drives the report map, score, people, disruption, ranked list, project sheets and exports. Its identity is scenario ID plus rank, and every view names it. The default is the shipped scenario's recommended rank; rank zero is the baseline. The old min_gain shortlist is a separately named option, never silently mixed with the selected package. Each saved step names its project IDs and full-precision totals. A report archive holds a record and sheet for every selectable project. Embedded data must support selection offline; no network or local-file fetch is needed. This amends FR-9.1, FR-9.3, FR-9.4 and FR-13.15. | MUST |
| FR-15.3 | Put the selected package, council ask, top projects and links to report sections before full curve tables and the appendix. Full curve tables are folded by default and stay usable without scripts. At 390 CSS pixels and at desktop width the report body has no sideways scroll. Keyboard input changes scenario and rank, and a text status announces the selected package. Print the selected package, its totals and method. Keep the 8 MB report limit. | MUST |
| FR-15.4 | Keep road reserve, carriageway and usable verge as distinct fields, each with source, date, range and confidence. Reserve minus assumed verges is an estimate of carriageway, not an observed verge width. A verge path cannot be marked proven to fit from that circular estimate. If usable space or constraints are unknown, mark needs_survey and list what to check: footpath space, trees, utilities, drainage, driveways, bus stops and narrow points. A model margin and source confidence are separate labels. Default picks exclude fixes whose safety or usable width is unproven; show them as survey options in a separate layer. Preserve other valid fixes. An empty confirmed shortlist is valid when no eligible fix has enough gain; state why and retain survey options. This also amends the non-empty rule of FR-8.12, without lowering min_gain. This amends FR-5.3 to FR-5.6 and FR-6.4. | MUST |
| FR-15.5 | Track all-ages status as confirmed, assumed or unknown, with reasons. A nearby signal alone does not prove the crossing movement has a safe signal phase. A refuge with no usable width is unknown. A path with no width or access evidence cannot be called confirmed safe. Main access and picks use confirmed links; an explicit assumptions scenario may use assumed links with a visible label. Audit crossing movements and turning conflicts, not just whole junction proximity. Public prose says meets the model's all-ages criteria, never guarantees child safety. This amends FR-4.4, FR-4.6 and FR-4.10. | MUST |
| FR-15.6 | For each package, count unique people gaining at least one safe destination, unique people per place type, and gains counted by type as distinct measures. A person who gains a school and station counts once in the first and twice in the third. A person who gains two schools counts once in the school count. Derive unions from population-node membership; do not add rounded per-type counts to claim unique people. Apply the same names to figures, slider, summaries, sheets and review reports. Population is an estimate of people, not a count of households. | MUST |
| FR-15.7 | Full verification takes outputs, region and snapshot. Apply each package's fixes to the baseline graph, recompute crossing and street safety, usable-width margins and access, then compare saved values with independent results. Check hashes, exact project sets, unique people, cumulative totals, score range and monotonicity, stop policy, truncation and figure recipes. A changed aaa_after flag, score or stop must fail even if the stored hashes and sums were updated to agree. Without region and snapshot, label the old mode structural only. Releases run full verification on their own output, not just unit tests. | MUST |
| FR-15.8 | Split broad public checks into parts. Mark a requirement met only if output checks cover every part for this release. Missing output proof is tested only or not built yet; it is never met. Checking for no host paths does not prove matching bytes. Checking viewport and print tags does not prove layout, chart labels or keyboard use. Recompute figure claims, including the stop, from underlying full-precision data rather than reading a saved answer. Show the check command, source files and result. This amends FR-13.11 and FR-13.14. | MUST |
| FR-15.9 | A snapshot states required adapters and effective dates. Its immutable ID includes a revision when added sources would change prior bytes; never overwrite a published snapshot. A fresh complete snapshot is required before changing the public default. Verify checks required artifacts as well as listed hashes, and names each missing adapter. A source that is current rather than historical states that fact beside the pinned OSM date. Report data quality by road class and project: observed, inferred, default and missing speed, ADT, lanes, parking, widths, bike facility and crossings. State the fraction of baseline and proposed links with uncertain evidence. Extend FR-12.1 and FR-2.5. | MUST |
| FR-15.10 | Sensitivity includes the variants of FR-12.2 plus candidate-pool size and assumed-versus-confirmed links. Compare top-ten IDs, rank changes, completed trips, selected package score and unique people. Use the same input snapshot and report all parameter differences. Test a pair of fixes that only gives a useful connection together, and compare greedy picks with an exhaustive solution on a small graph. Call the real-region result a heuristic; do not claim a global optimum. | MUST |
| FR-15.11 | Official traffic, speed, crash, ABS population and destination adapters retain provenance, effective date, joins, unmatched counts and uncertainty. Validate matched speeds, width and crossing status against independent records. Report population inside the council separately from the buffer, partial-cell treatment, unsnapped people and destinations, and entrance snapping errors. Destination access uses actual public entrances where known; an unknown entrance is labelled. Extend FR-10.3 to FR-10.7 and FR-7.3. | MUST |
| FR-15.12 | A field audit file holds measured street widths, usable verge, crossing movement, refuge width, path access, date, source and permission for evidence. The check compares it with model values and reports errors and unknowns without changing the raw observations. Start with a diverse sample of road and path types. If observations cannot be obtained, ship the audit template and name the missing evidence; do not invent measurements or call the field validation done. | MUST |
| FR-15.13 | A named council benchmark distinguishes existing, planned, funded and aspirational routes, owner and source date. Report overlap and differences using FR-12.3; distinguish missing OSM from a real missing link. Import official geometry if available. If only a PDF exists, retain a sourced trace and its uncertainty; do not label it official geometry. For the first pilot compare feasible options for Bayside EW6 or Mascot-Eastlakes, complete destination trips, disruption and delivery needs. | MUST |
| FR-15.14 | Project sheets give complete-trip links, destinations, observed problem, alternatives, uncertainty, owner, approvals, survey needs, dependencies, capital and upkeep cost ranges and the next council decision. Cost inputs have currency, base year, source and exclusions; missing costs remain unknown, never zero. Spending, space changes and weighted disruption are separate measures. Budget selection states its constraints and unmet needs. No contact or publication to third parties is authorised by this row. | MUST |
| FR-15.15 | Add aggregated access views for children, older people and households without cars only from sourced data. State coverage, units and missing groups. Do not infer protected traits from names or locations. Show whether each staged package changes access gaps, along with total access, and retain the same graph and trip rules for all groups. | MUST |
| FR-15.16 | Reuse graph, baseline access and immutable stage results across scenarios using snapshot, config, code and schema hashes as cache keys. Cache use must give equal bytes to uncached runs and fail on stale keys. Provide a fast shortlist mode and a full scenario mode with explicit labels. Keep the full-run NFR-3 and scenario FR-8.14 time and memory limits; fast-mode success does not prove full-mode performance. Log wall time, CPU, peak RSS, runner details and cold/warm state. | MUST |
| FR-15.17 | CI proves matching bytes and NFR-3 on Bayside with the shipped settings and full inputs. Prove Cambridge end to end with no source change. Profiles declare traffic_side left or right; street-side fields and contraflow work in mirrored fixtures. New-region guidance states which standards and data are needed rather than claiming every country has been validated. These extend FR-11.5, FR-11.7 and FR-11.8. | MUST |
| FR-15.18 | Private route inputs, claims, replies and outputs stay under git-ignored data/private. The CLI rejects a private output outside that root, and release discovery excludes it regardless of a misplaced public flag. Only hashes and verdict counts may be saved as a private row's public proof. Route publication requires the recorded permission of FR-14.12. | MUST |
| FR-15.19 | README gives current implemented and pending work, the latest public report, fast and full commands, score meaning and limits, and headline figures with rebuild commands. Only assert portability that has end-to-end evidence. The public ask names a concrete next council decision, with facts separated from assumptions. | MUST |

## 4. Work rules

For each row, read only the named requirements, their acceptance cases and the specs it amends. Add small failing cases before code. Save one real proof with the exact command, config hash, snapshot hash and commit. Do not lower min_gain, narrow the input area or change a standard to make a result pass. The field audit may need a person, but all work independent of it must continue with uncertainty shown.

## 5. Sources
