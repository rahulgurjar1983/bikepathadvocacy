# Agent notes

Tips and traps that carry across loop turns. Add what you learn. Keep each note short.

## Notes

- Run every gate through `scripts/gate.sh`; CI runs the same script.
- Tests run with `--import-mode=importlib` and `pythonpath = ["src", "."]`, so `tests/` and `gates/tests/` may hold files with the same name.
- The red-green gate runs each new or changed test against the base code. Put a new case in a new test function, never as a new row of a test that already passes.

- The smoke test builds the Docker image for real. A cold build took about 8 minutes here, so run it once and expect the pre-push gate to be slow.
- The Dockerfile pins the base by digest. Rebuild the pin with `docker buildx imagetools inspect python:3.12-slim`.
- Region and profile checks live in `src/bikeplan/config.py`. `config_hash` takes any dataclass or dict, so the profile loader (P1.2) can reuse it. PyYAML is the one runtime dependency.

- Profiles live in `profiles/<id>.yaml`; `load_profile(id, directory)` reads them. `Num` keeps `value`, `source` and an `assumption` flag. Tests build bad files from a copy of the real `au-nsw` file.
- Region files live in `regions/<id>.yaml`. `test-grid` points at `tests/fixtures/test-grid/snapshot/boundary.geojson`, which the P11 fixture row must create. `bikeplan config show` prints one `key value (source)` line per profile value.
- `uv add <package>` works on this host and may use the network. Python's built-in request tools work with the local replay server used by snapshot tests.

- `boundary_geojson` joins relation ways into rings in plain Python, because shapely is not in the offline lock. `fetch_boundary` stores the raw reply only while it checks it, so an open relation leaves no file. The network query asks for XML; gzip is the job of the fetch command row.
- `fetch_snapshot` in `src/bikeplan/snapshot.py` runs each adapter from the `ADAPTERS` dict as `adapter(region, box, out_dir)` and expects a list of `ManifestEntry` with `path` relative to the out dir. `kontur_population` is now in it.
- The Bayside network fetch takes about 3 minutes and gives a 5.5 MB gzip. Run it in the background.
- The Kontur adapter finds the country file with the HDX query `fq=organization:kontur AND res_url:*kontur_population_<CC>_*`. A plain text search for the code ranks other countries first.
- Kontur files have no spatial index, so the cut reads all rows. Australia has 517689 rows; the cut takes seconds.
- `tests/fixtures/kontur/` holds a real HDX reply and a 28-hexagon cut of the real Australia file near 151.12, -33.93.
- On 2026-10-07 `overpass-api.de` gave 504 on the Bayside network query twice. The run passed through `--endpoint https://overpass.private.coffee/api/interpreter` in 11 minutes.
- To check a real cut, run `python3 -I -c` with `sqlite3`: sum `population` in `population.gpkg`, then sum the source rows with the same `h3` values. Both gave 873592 for Bayside.
- `verify_snapshot`, `publish_snapshot` and `pull_snapshot` live in `src/bikeplan/snapshot.py` and call `gh` through `run_gh`. Publish verifies first and uploads with `--clobber`; pull copies the manifest into the cache folder so verify can read it. Tests put a stand-in `gh` script on `PATH`.
- The Bayside snapshot fetch from `https://overpass.private.coffee/api/interpreter` takes about 15 minutes. Run it in the background. The files live in `data/cache/au-nsw-bayside/2026-10-01/` and the release is `snapshot-au-nsw-bayside-2026-10-01`.
- Manifest paths must be relative to the snapshot folder. A relative `--out` once leaked into the boundary path and only a real verify caught it.
- `bikeplan.network.build` reads `network.osm.gz` and `boundary.geojson` from the snapshot folder. It builds with `bidirectional=False`, adds the contraflow reverse edges by hand, then simplifies with `edge_attrs_differ=KEPT_APART`. Add each new tag to `WAY_TAGS`, or it is lost. `bidirectional=True` drops the `oneway` flag, so do not use it. A Bayside build takes about a minute.
- Speed, lanes and ADT are set in `mark_bike_access` before simplify, from `maxspeed`, `lanes`, `lanes:forward` and `lanes:backward`. Contraflow reverse edges carry `contraflow=True` and get `lanes_dir` 0. Every tag kept apart in simplify splits edges, so each new tag raises the Bayside edge count (189160 to 189386 here). Non-road classes such as `cycleway` get speed `None`, 0 lanes and 0 ADT. The tag fixture is `tests/fixtures/network/tags.osm`; the older `cases.osm` test pins its way list, so add new cases to the new file.
- Side fields (`bike_facility`, `bike_lane_width_m`, `parking`) are set in `set_side_fields` before simplify. The side is picked from the edge direction and assumes left-hand traffic: a forward edge reads `left`, a reversed edge reads `right`. A right-hand region needs a profile field for this. `project_graph` drops `None` values, so `set_lengths` puts the optional fields back as `None`. The fixture is `tests/fixtures/network/sides.osm`. Lane width uses `parse_length` with no 2 m to 40 m limit.
- `build` sets `segment_id` in `set_lengths` from the OSM way and the sorted end node IDs. `graph.graph["points"]` holds signal, refuge and crossing nodes read straight from the XML with `iterparse`, projected to the graph CRS, so simplification cannot drop them. `bikeplan network summary` rebuilds the graph, so a Bayside run takes about 3 minutes. The fixture is `tests/fixtures/network/segments.osm`.
- `bikeplan.stress` holds the Furth tables. `mixed_traffic_lts(edge_data)` reads `lanes_total`, `lanes_dir`, `oneway`, `lane_markings`, `highway`, `lanes`, `width_tag_m`, `speed_kmh` and `adt`. Parking sides for the wide one-way test come from the raw `parking:*` tags, and an untagged side counts as no parking. `project_graph` drops `None`, so non-road edges have no `speed_kmh` key. The `lane_markings` tag is in `WAY_TAGS`; the Bayside edge count stayed 189386. Tests that build a graph take about 35 seconds, so run them with a Bash timeout above 120 s.
- `painted_lane_lts(data, parking_lane_m, class_parking)` in `bikeplan.stress` scores painted lanes. The caller passes `profile.widths_m.parking_lane.value` and `road_class(highway, profile).parking.value` (use `road_class`, since `secondary_link` has no profile key). A contraflow edge counts as one lane, and zero lanes count as one: Bayside has painted-lane edges with `lanes_dir` 0 that are not contraflow. Edges with `lanes_total` 0 are skipped by the real run.
- `edge_lts(data, profile)` and `is_aaa(data, lts, profile)` in `bikeplan.stress` take the whole profile. A painted lane is AAA only when `painted_lanes_count` is true, even if its speed and ADT meet a mixed-traffic rule. Both shipped profiles set it false, so tests flip it with `dataclasses.replace`. Bayside AAA km is mostly `none` edges, where the AU default ADT and speed meet the mixed rule.
- `junction_points(graph)` flags each node with a `signal` and `refuge` within 25 m of the point layer. `raise_for_crossings(graph, lts, profile)` takes a dict of own LTS by edge key `(u, v, k)` and returns `(final, crossings)`; every edge key needs an entry, so give non-road edges (no `speed_kmh`) an LTS of 1 first. Main streets need lanes and a `speed_kmh` key. The junction fixture is `tests/fixtures/network/junctions.osm` (junctions 8100 to 8500). Bayside: 9352 signalised nodes, 5714 with a refuge, 3136 edges raised. Refuge width is not in OSM, so any refuge counts as meeting the 1.8 m rule.
- `bikeplan stress` calls `write_stress(graph, profile, out)` in `bikeplan.stress`. Edges with no motor traffic data score LTS 1 and are never AAA unless off-road. `stress.geojson` for Bayside is 89 MB, so only `stress_summary.json` is committed. The run takes under 2 minutes. Summary km count directed edges, so a two-way street counts twice. `edge_reason` explains a speed or ADT rule failure before it says the LTS is above 1, as the spec example does.
- `bikeplan.width` holds `lane_estimate(data, profile)`, `tag_estimate(data)` and `estimates(data, profile)`, which returns kept estimates and `(source, reason)` drops. Parking sides read both raw sides with `parking_on_side`, so an untagged side follows the class default; a residential street with no tags counts two parked sides. The network already drops tags under 2 m or over 40 m, so the 3 m limit drops the 2 m to 3 m ones here (97 on Bayside). The Bayside run for the artifact takes about 90 seconds.
- `bike_segments(graph)` in `bikeplan.network` groups bike-legal edges by `segment_id` with the length inside `graph.graph["boundary"]`. Use it for any km total. A direction-by-direction sum counts two-way streets twice.
- `reserve(segment, parcels)` in `bikeplan.width` takes a shapely `LineString` and a list of shapely polygons, both in metres. Lines sit at the middle of each 20 m step, so a parcel edge at a round number is never hit on its corner. A confidence drop goes `low` to `very low`. `shapely` comes with osmnx and is not a listed dependency.
- `fuse(data, profile, reserve_m, spread_m)` in `bikeplan.width` keeps every estimate in rank order (adapter, osm_tag, reserve, lanes) and picks the first. An adapter width comes in as the edge key `width_measured_m`, which no adapter sets yet. `width_summary(graph, profile)` counts each bike segment once by its `inside_m`, and a segment with no estimate counts as `none none`. `check_links(lat, lon)` gives the two links; the summary does not yet write them to a file. Bayside: 518.119 km lanes, 2.556 km tag, 70.424 km none. The run takes about 90 seconds.
- `bikeplan.fit` takes a segment as a plain dict: edge fields plus `width_m` and `reserve_m` from `fuse`, and an optional `median_m`. `cross_section` puts the spare strip last, and the spare used for fitting adds back any painted lane. `options` returns the six fixes in spec order, each with `fits`, `needs_m`, `spare_m`, `margin_m`, `reason`, `layout` and `widths`. A fix that does not fit reports the minimum widths it tried. Quietway checks ADT before class, so a tertiary street says "ADT over 2000".
- `bikeplan.fit.options` adds `robust` (`robust`, `check on site`, or `None` when it does not fit) by refitting at the segment's `width_low_m`, and a `disruption` dict of counts from `length_m`. `disruption_score(counts, weights)` takes `region.proposals.disruption_weights`. Parking spaces count per removed side, rounded per side.
- `bikeplan.fit.choose(segment, profile, weights, edges=None)` returns `status` (`aaa`, `fix` or `no_fit`), `fix`, `score`, `candidates` (each with `accepted` and `rejected`), `reasons`, and `before` and `after` strips. `edges` are the segment's edges; edges with `bike_ok` false are not rescored. `after` leaves out the spare strip when it is zero. Pair cycleways go at the kerbs; the two-way one goes on the unparked side, else the left. Rescoring uses `own_lts` and `edge_aaa` from `bikeplan.stress` on a copy of each edge.
- `bikeplan.report.write_report(graph, region, profile, out)` writes `segments.csv` (one row per bike segment: `length_m`, `lts`, `aaa`, `width_source`), `figures.json`, `report.html` and `SHA256SUMS`. Each figure is a km sum over `segments.csv`, and its recipe reads only that file. `MISSING_STAGES` lists the stages with no code; remove a name when its stage joins the report. Bayside: F1 591.099, F2 114.676, F3 70.424 km; the run takes under 2 minutes.
- `snapshot pull` puts the files in `data/cache/<region>/<snapshot id>`, which is git-ignored. Run reports from there.
- `Region.report.author` is `None` when the region file leaves `report` out. `bikeplan report` fails with `report.author` in the message when it is `None`; `test-grid` has no author on purpose.
- In `report.py`, `link(item)` wraps the value, unit and ID in one anchor, and `entry(item)` writes the appendix article for a figure. Any new number in the report text must go through `link`, because a test fails on a digit outside a link and the appendix. The report tests build the full test grid report and take about 4 minutes.

- P4.7: `is_shared_path` in `stress.py` marks a bike-ok `path` or `footway` that is not off-road. It scores LTS 1 and is AAA by width (FR-4.10). Unknown width is AAA and says so in the reason. Off-road paths raised by a crossing still say `not AAA: no motor traffic data`; the reason is misleading but the AAA flag is right.
- R1.3: the report text is scored by `tests/test_report_voice.py` with `pre`, `code`, `style` and `head` left out, as the gate does for Markdown code. Put hashes and recipes in `code` or `pre`. A project word used outside the appendix needs a line in `GLOSSARY` in `report.py`; the test fails and names the word. Chart bars carry text labels and a table with `data-for` set to the SVG `id`; keep digits out of SVG text, because FR-13.2 allows numbers only inside figure links. The Bayside report run takes about 3 minutes.
- R1.5: the map is drawn by `src/bikeplan/assets/map.js` on the pinned Leaflet 1.9.4 files in the same folder. `write_report` now takes the snapshot folder, for `boundary.geojson` and the optional `places.json`, and writes `map.json` (F4 reads it). The Leaflet source sits in the page head, so tests that read raw HTML must strip `script` and `style` first (`markup` in `tests/test_report_voice.py`). Browser tests use selenium with the chrome on the host and `--proxy-server=http://127.0.0.1:9` to block the network. Tooltip text is read with `textContent`, since the tooltip fades in. Words like "very" are banned in report text. `tests/fixtures/network/cases.osm` has all four stress levels.

- `scripts/release.sh` (it replaced `release-report.sh`) reads `BIKEPLAN` (default `uv run --frozen bikeplan`) so tests can run it with a stand-in command, and `RELEASE_OUT` to keep the upload folder. It makes `<id>-report.html` and `<id>.tar.gz` per report, `<id>-review.html` per public review, `artifacts.tar.gz`, `index.html` and one `SHA256SUMS`. It copies reports forward only when `git diff HEAD^ HEAD` shows none of the FR-13.7 paths. The review inputs come from `routes/<id>/review.yaml` keys `public`, `route`, `claims` and `region`, with paths relative to that folder; `bikeplan review` is not built yet. The operator still adds the CI `release` workflow (FR-13.8).
- R1.6: `snapshot_date(region)` in `report.py` writes the snapshot date inside the appendix, because a digit outside a figure link or the appendix fails FR-13.2 and a `datetime` attribute looks like a phone number to the FR-13.5 test. The review report (FR-14.8) is not built yet, so its determinism test belongs to V1.5. `tests/test_report_deterministic.py` fakes the clock by patching `time.time` in a child process.
- P6.4: `junction_fixes(graph, profile)` in `bikeplan.fit` gives one fix per unsignalised junction whose side legs are AAA on their own stress but held back by the crossing: `refuge` when table 8 gives LTS 1, else `signals`; a junction that already has a refuge goes straight to `signals`. `fit_summary(graph, profile, weights)` runs `choose` on each bike segment with traffic, using `fuse` for width and no reserve (no parcels in the snapshot yet, so `verge_path` is 0 km). `robust_share` counts segments, not km. Segments with no motor traffic data are skipped. Bayside run takes about 2 minutes.
