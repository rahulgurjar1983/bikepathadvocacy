# Agent notes

Tips and traps that carry across loop turns. Add what you learn. Keep each note short.

## Notes

- Run every gate through `scripts/gate.sh`; CI runs the same script.
- Tests run with `--import-mode=importlib` and `pythonpath = ["src", "."]`, so `tests/` and `gates/tests/` may hold files with the same name.
- The red-green gate runs each new or changed test against the base code. Put a new case in a new test function, never as a new row of a test that already passes.

- The smoke test builds the Docker image for real. A cold build took about 8 minutes here, so run it once and expect the pre-push gate to be slow.
- The Dockerfile pins the base by digest. Rebuild the pin with `docker buildx imagetools inspect python:3.12-slim`.
- Region and profile checks live in `src/bikeplan/config.py`. `config_hash` takes any dataclass or dict, so the profile loader (P1.2) can reuse it. PyYAML is the one runtime dependency.

- Profiles live in `profiles/<id>.yaml`; `load_profile(id, directory)` reads them. `Num` keeps `value`, `source` and an `assumption` flag. Tests build bad files from a copy of the real `au-nsw` file.
- Region files live in `regions/<id>.yaml`. `test-grid` points at `tests/fixtures/test-grid/snapshot/boundary.geojson`, which the P11 fixture row must create. `bikeplan config show` prints one `key value (source)` line per profile value.
- `uv add <package>` works on this host and may use the network. Python's built-in request tools work with the local replay server used by snapshot tests.

- Side fields (`bike_facility`, `bike_lane_width_m`, `parking`) are set in `set_side_fields` before simplify. The side is picked from the edge direction and assumes left-hand traffic: a forward edge reads `left`, a reversed edge reads `right`. A right-hand region needs a profile field for this. `project_graph` drops `None` values, so `set_lengths` puts the optional fields back as `None`. The fixture is `tests/fixtures/network/sides.osm`. Lane width uses `parse_length` with no 2 m to 40 m limit.

The fixture is `tests/fixtures/network/segments.osm`.
- `bikeplan.stress` holds the Furth tables. `mixed_traffic_lts(edge_data)` reads `lanes_total`, `lanes_dir`, `oneway`, `lane_markings`, `highway`, `lanes`, `width_tag_m`, `speed_kmh` and `adt`. Parking sides for the wide one-way test come from the raw `parking:*` tags, and an untagged side counts as no parking. `project_graph` drops `None`, so non-road edges have no `speed_kmh` key. The `lane_markings` tag is in `WAY_TAGS`; the Bayside edge count stayed 189386. Tests that build a graph take about 35 seconds, so run them with a Bash timeout above 120 s.
- `painted_lane_lts(data, parking_lane_m, class_parking)` in `bikeplan.stress` scores painted lanes. The caller passes `profile.widths_m.parking_lane.value` and `road_class(highway, profile).parking.value` (use `road_class`, since `secondary_link` has no profile key). A contraflow edge counts as one lane, and zero lanes count as one: Bayside has painted-lane edges with `lanes_dir` 0 that are not contraflow. Edges with `lanes_total` 0 are skipped by the real run.
- `edge_lts(data, profile)` and `is_aaa(data, lts, profile)` in `bikeplan.stress` take the whole profile. A painted lane is AAA only when `painted_lanes_count` is true, even if its speed and ADT meet a mixed-traffic rule. Both shipped profiles set it false, so tests flip it with `dataclasses.replace`. Bayside AAA km is mostly `none` edges, where the AU default ADT and speed meet the mixed rule.

Bayside: 9352 signalised nodes, 5714 with a refuge, 3136 edges raised. Refuge width is not in OSM, so any refuge counts as meeting the 1.8 m rule.

Edges with no motor traffic data score LTS 1 and are never AAA unless off-road. `stress.geojson` for Bayside is 89 MB, so only `stress_summary.json` is committed. The run takes under 2 minutes. Summary km count directed edges, so a two-way street counts twice. `edge_reason` explains a speed or ADT rule failure before it says the LTS is above 1, as the spec example does.

Parking sides read both raw sides with `parking_on_side`, so an untagged side follows the class default; a residential street with no tags counts two parked sides. - `bike_segments(graph)` in `bikeplan.network` groups bike-legal edges by `segment_id` with the length inside `graph.graph["boundary"]`. Use it for any km total. A direction-by-direction sum counts two-way streets twice.

Lines sit at the middle of each 20 m step, so a parcel edge at a round number is never hit on its corner. An adapter width comes in as the edge key `width_measured_m`, which no adapter sets yet. `width_summary(graph, profile)` counts each bike segment once by its `inside_m`, and a segment with no estimate counts as `none none`. `check_links(lat, lon)` gives the two links; the summary does not yet write them to a file. - V1.2: `bikeplan.review.route_figures(graph, profile, sections)` gives per-section and total figures. Km by facility and level sum the lengths of matched edges plus the off-network stretches, so a route that cuts across half an edge counts the whole edge. A break is a run of non-AAA items (edges and off-network stretches) in route order, found by projecting each edge midpoint on the route. A crossing is a node between two matched edges where one route leg is not part of the main street (`main_street`); a signal gives crossing LTS 1. `build` now keeps the `opening_hours` way tag and reads `barrier` gate nodes into `graph.graph["gates"]`; a gate flags matched edges within 5 m. Import `tests.route_helpers` from a script with `importlib`, since a plain import fails outside pytest.
- R1.11: the page map is `map.json` itself: `merge_pieces` joins touching segments with the same name, street type, level, safety and fix (shapely `linemerge`), keeping five fields and `lines`. The per-segment detail (length, width source, fix) lives in `segments.csv`. F4 now counts pieces. `page-data` keeps only summary, projects and project shapes; the full network stays in `network.geojson` from `bikeplan run`. The Bayside report takes about 9 minutes to build. The Bayside size check is a manual step in VERIFICATION.md, since the full snapshot is not in git.
- R1.12: `bikeplan checks` now needs `--release <folder>` and fails hard with no report `.html` there. Status is "met" only for a spec ID in `checks.OUTPUT_CHECKS` (FR-13.6, FR-13.10, FR-13.13) whose check passes on every report file; a passing test with no output check gives "tested only". The no-tools step reads the row's `Expect:` and `Artifact:` lines from `VERIFICATION.md` and sends the reader to `artifacts.tar.gz`, never to the file itself. Add an output check for a new ID by adding one function and one `OUTPUT_CHECKS` entry.
- V1.3: `bikeplan.network.build` calls `bikeplan.elevation.set_grades` when the snapshot holds `elevation.tif`, giving each edge `rise_m` and `grade_pct` from node to node (bilinear, any raster CRS). `copernicus_glo30` downloads whole 1 degree COG tiles from the AWS bucket and cuts them to the box; Bayside needs one tile. `route_figures` totals now hold `steep` (runs of chained route edges at or above `grade.steep_pct` with one sign, kept when long enough) and `grade_limits`. Without `elevation.tif` there is no grade and no flag. The review report page for these flags comes with V1.5.
- V1.4: `route_figures(graph, profile, sections, region, snapshot)` adds `fixes`, `no_fit`, `disruption` and, on the total, `access` when it gets a region. It reuses `planning_network`, so a street edge that is not AAA and has no planning entry is `no_fit`. A segment fix is scaled by route metres over segment length; a junction fix counts once per section. `access` adds the route's bike-legal edges (both ways) to the AAA set and reruns `safe_reach` on the baseline `within`; `homes_gaining_safe_reach` is people newly safe to any place, `safe_people_gain` is per type like `propose`. `ranked` runs `write_propose` and takes whole projects in rank order while their km fit the route km. Claims use flat keys `measure`, `op`, `value` (or `outside`); `claim_verdicts` is in `bikeplan.review`, and `--claims` on `route figures` writes `verdicts.json`. "Partly" means a miss of at most 20% of the claimed value.
